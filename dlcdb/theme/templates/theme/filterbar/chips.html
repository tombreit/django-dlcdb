The view's own default ordering is not a change and gets no chip. The wrapper carries no outer margin, so a consuming template can drop it into its own status row (e.g. next to a result count) — the component itself knows nothing about counts. With JS, clicking a chip clears the matching input in the bar's form and lets the form's own hx-get fire (one request path, widgets stay in sync). The href is the no-JS / middle-click fallback and reloads the page with that value removed.
