Owns the header band, the two-column split and the ``can_change`` fork, so a page only supplies what is actually its own. Extension points are blocks with defaults, the way the Django admin exposes ``object-tools`` — override a block, or extend it with {{ block.super }}. Expects from the view: ``can_change``, ``form``, ``form_action``, ``index_url``. Blocks: detail_page_class full class attribute for the page wrapper, including the ``class=`` itself, so pages that need none emit a bare
(e.g. ' class="device-page"') detail_leading avatar / icon tile left of the title detail_title_class extra

classes, with a leading space (e.g. ' font-monospace') detail_title the heading itself detail_meta badges and secondary text under the heading object_tools header-right actions; defaults to the back link detail_form_class full class attribute for the
, as above detail_form_fields the form body (an app's _form_fields.html) detail_readonly_notice why the page is read-only; defaults to the permission wording, since that is the common case detail_readonly read-only rendering of the object detail_sidebar the col-lg-4 column Read-only pages that are read-only *by design* (assets/records) do not use this frame: their header carries a breadcrumb band instead and there is no form. {% endcomment %} {% block body %} {% block detail_header %}
